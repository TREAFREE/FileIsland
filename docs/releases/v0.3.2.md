# File Island 0.3.2 — unsigned early access

File Island 0.3.2 focuses on first-run clarity and a reliable output handoff. Converted files now remain available in a persistent native result shelf, where they can be previewed, selected, copied, revealed in Finder, or dragged directly into Finder and compatible applications.

## What changed

- Added a one-time, nonactivating Island guide for Finder drag-and-drop and Command-O.
- Added a native result shelf with Quick Look thumbnails and compact filenames.
- Small result sets are centered; larger batches remain horizontally scrollable with a persistent compact scrollbar.
- Single and multi-selection results can be copied, revealed in Finder, or dragged out with native file URLs.
- Sequential drag-out remains available until the user explicitly dismisses the result shelf.
- Output-folder security-scoped access is retained while results remain visible.
- Published result URLs are no longer rejected by a second sandbox readability lookup during collection-view reuse.
- Settings now expose working website, release, issue, privacy, and third-party notice destinations.
- The About pane uses File Island artwork, while Appearance adds a live opacity preview and reset action.
- Output-folder paths are presented compactly without exposing unnecessary home-directory detail.

## Install

Download `FileIsland-0.3.2-unsigned.dmg` and its checksum, verify it with `shasum -a 256`, open the DMG, and drag **File Island** to **Applications**.

File Island 0.3.2 requires macOS 15 or later. The App contains universal arm64/x86_64 binaries, FFmpeg, ffprobe, the AVFoundation media validator, and its preset catalog. Users do not need Homebrew, Python, Node.js, or a separate media runtime.

This early-access build has an ad-hoc code signature, not an Apple Developer ID signature, and it has not been notarized. macOS may require **System Settings → Privacy & Security → Open Anyway** after the first launch attempt. Do not disable Gatekeeper.

## Existing boundaries

- Fast sharing split accepts audited H.264 MP4/MOV with optional AAC audio and requires at least one positive size or duration limit.
- MP3 remains input-only; output is M4A, WAV, FLAC, or AIFF.
- WebP remains image input-only; verified image outputs are JPEG and PNG.
- Precise re-encoded splitting and named platform rules are not included.
